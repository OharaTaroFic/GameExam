## 症状

- 作成元PCでは問題なくビルドできる
- **別のPCで実行すると**、Unityは見つかり、ビルドは開始され、しばらく進行するが、最終的に失敗する
- （「Unityが見つかりません」等の初期エラーではない。ある程度ビルド処理が進んでから落ちる）

## すでに除外できた原因

| 候補 | 除外理由 |
|---|---|
| コード内にPC固有のパスがハードコードされている | `C:\Users\...` やユーザー名、特定ドライブ決め打ちの記述はコード全体を検索したが無し。すべて `$PSScriptRoot`（[tools/build.ps1:10](tools/build.ps1#L10)）を起点に動的計算しているため、PCが変わっても参照先自体は自己解決する |
| Unityライセンス未認証 | ライセンス未認証の場合は`-batchmode`起動直後に即エラー終了するのが通常だが、今回は「しばらく進行してから失敗」なので合わない |
| Unityバージョンの完全不一致 | バージョンが合わなければ [tools/build.ps1:82](tools/build.ps1#L82) の時点でそもそもビルド対象から静かに除外（スキップ）される。今回はビルドが実際に開始・進行しているので該当しない |

## 有力な原因候補（優先度順）

### 1. WebGL Build Support モジュールがそのバージョンに入っていない（最有力）

Unity Hubでは「エディタ本体」と「WebGL Build Support」モジュールはバージョンごとに別installになる。
[tools/build.ps1:48-54](tools/build.ps1#L48-L54) は `Editor\Unity.exe` の存在有無しかチェックしておらず、**WebGLモジュールの有無は未検証**。

モジュールが無くても、プロジェクトを開く・アセットインポート・スクリプトコンパイルまでは進行し、実際にIL2CPP変換／Emscripten処理に入る段階で初めて失敗する。「途中まで進んでから失敗」という症状と一致する。

複数バージョンがHubに入っている場合、**プロジェクトが要求する特定バージョンの方にだけWebGLモジュールが入っていない**、というズレが起きやすい。

→ **確認方法**: 該当PCのUnity Hub → 対象バージョンの「歯車アイコン」→ モジュール一覧で「WebGL Build Support」にチェックがあるか確認。

### 2. ディスク容量不足

IL2CPP変換・WebGL/Emscriptenの中間ファイルは1作品あたり数GB〜十数GB消費する。ビルド後半（`build.ps1`のフェーズ検出でいう「プログラム変換中」「ブラウザ用に変換中」付近、[tools/build.ps1:143-155](tools/build.ps1#L143-L155)）で容量が尽きて失敗するケースが多い。

→ **確認方法**: 該当PCのビルド先ドライブの空き容量。

### 3. パス長制限（260文字）

IL2CPPが生成する中間ファイル名は長くなりがち。ツール一式の設置場所が深い階層（OneDrive同期フォルダ、入れ子の深いデスクトップ配下など）だと、合計パス長がWindowsの制限を超えて失敗することがある。作成元PCでは浅い場所に置いていたが、別PCでは深い場所に置いている、という違いがあれば疑わしい。

→ **確認方法**: 該当PCでのツール一式の設置パスの深さ・長さ。

### 4. メモリ不足

WebGLのリンク・最適化処理（wasm-opt等）はメモリを大きく消費する。該当PCのRAMが少ないと途中でクラッシュ／失敗する可能性がある。

## 確定診断に必要な情報（次にやること）

1. 失敗したPCの `完成したゲーム\_ログ\<作品名>.log` の**末尾50〜100行**
   - `il2cpp` / `emcc` / `wasm` 関連のエラー → モジュール or メモリ関連の可能性
   - `Fatal error` / `out of memory` → メモリ不足
   - `path too long` / ファイルパスに関するエラー → パス長制限
   - `No space left` / ディスク関連 → 容量不足
2. 該当PCのUnity Hubで、対象バージョンにWebGLモジュールが入っているか
3. 該当PCのビルド先ドライブの空き容量
4. ツール一式の設置パス（深さ・OneDrive配下かどうか）
5. 該当PCの搭載RAM
